The shadcn/ui toggle group. With `type="single"` it behaves like a segmented
control: one indicator slides to whichever item is pressed (a FLIP on
`translate` and `scale`, as in [Tabs](/docs/components/tabs)). With
`type="multiple"` each item keeps its own on background. Every item presses
on a spring.

## Replacing shadcn

`npx shadcn add @godui/toggle-group` overwrites `components/ui/toggle-group.tsx`
and installs the GodUI [Toggle](/docs/components/toggle) it styles items with.
Exports, props and `data-slot` attributes match shadcn/ui new-york-v4, so
existing imports keep working. A single-select group renders one extra element,
an `aria-hidden` `<span data-slot="toggle-group-indicator">`.

## Usage

```tsx
import { ToggleGroup, ToggleGroupItem } from "@/components/ui/toggle-group";
```

```tsx
<ToggleGroup type="single">
  <ToggleGroupItem value="a">A</ToggleGroupItem>
  <ToggleGroupItem value="b">B</ToggleGroupItem>
  <ToggleGroupItem value="c">C</ToggleGroupItem>
</ToggleGroup>
```

## What's animated

| Interaction | Keyframe / mechanism | Properties | Easing | Duration |
| --- | --- | --- | --- | --- |
| Select (single) | FLIP (WAAPI) on the indicator | `translate`, `scale` | `ease-spring-snappy` | 260ms |
| Toggle (multiple) | on background snaps | none | none | none |
| Press | `transition` on `active:scale-[0.96]` | `scale` | `ease-spring-bouncy` | 260ms |

Before JavaScript runs, the pressed item paints its own background, exactly as
in shadcn. Under `prefers-reduced-motion` the indicator jumps and presses are
instant.
