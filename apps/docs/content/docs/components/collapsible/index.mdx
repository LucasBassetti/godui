The shadcn/ui collapsible with motion. shadcn's version doesn't animate at
all. GodUI uses the same snap-then-FLIP approach as
[Accordion](/docs/components/accordion): the panel's height changes in one
step, the panel slides in, and the elements after the Collapsible in its
parent slide from where they were to where they now are. Only `translate`
and `opacity` animate.

## Replacing shadcn

`npx shadcn add @godui/collapsible` overwrites `components/ui/collapsible.tsx`.
Exports, props and `data-slot` attributes match shadcn/ui new-york-v4, so
existing imports keep working. It also installs `godui-motion`, which includes
the `useFlipGroup` hook it uses.

## Usage

```tsx
import {
  Collapsible,
  CollapsibleContent,
  CollapsibleTrigger,
} from "@/components/ui/collapsible";
```

```tsx
<Collapsible>
  <CollapsibleTrigger>Can I use this in my project?</CollapsibleTrigger>
  <CollapsibleContent>
    Yes. Free to use for personal and commercial projects. No attribution
    required.
  </CollapsibleContent>
</Collapsible>
```

## What's animated

| Interaction | Keyframe / mechanism | Properties | Easing | Duration |
| --- | --- | --- | --- | --- |
| Open | height snaps; panel `godui-slide-in-from-top`; following siblings FLIP | `opacity`, `translate` | `ease-spring-snappy`; FLIP `ease-out-expo` | 260ms |
| Close | panel `godui-fade-out`, then height snaps; following siblings FLIP | `opacity`, `translate` | `ease-out-expo` | 150ms + 260ms |

Only the Collapsible's direct siblings move smoothly. Content further up the
tree moves in one step. With `asChild` on `CollapsibleContent`, the panel
still slides in, but the siblings don't FLIP.

Under `prefers-reduced-motion` siblings jump to their new position and the
panel fades for 150ms.
