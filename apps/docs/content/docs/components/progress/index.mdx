The shadcn/ui progress bar. The fill is always full width and slides into
place with `translateX`, so a new value glides there on a smooth spring and
the bar never resizes. Leave `value` out and it turns indeterminate: a shorter
bar sweeps across the track on a loop. Only `transform` animates.

<Example label="Default" story="ui-progress" code={`"use client";

import { Progress } from "@/components/ui/progress";
import * as React from "react";

export function ProgressDemo() {
  const [progress, setProgress] = React.useState(13);

## Replacing shadcn

`npx shadcn add @godui/progress` overwrites `components/ui/progress.tsx`.
Exports, props and `data-slot` attributes match shadcn/ui new-york-v4, so
existing imports keep working. It also installs `godui-motion` (easings,
keyframes, the FLIP hook) into your project, plus the
`godui-progress-indeterminate` keyframe.

One fix rides along: shadcn reads `value` but never hands it to Radix, so its
bar has no `aria-valuenow` and always reports `data-state="indeterminate"`.
GodUI passes `value` through, so screen readers hear the percentage and only a
missing value counts as indeterminate.

## Usage

```tsx
import { Progress } from "@/components/ui/progress";
```

```tsx
<Progress value={33} />
```

## What's animated

| Interaction | Keyframe / mechanism | Properties | Easing | Duration |
| --- | --- | --- | --- | --- |
| Value change | `transition` | `transform` | `ease-spring-smooth` | 380ms |
| Indeterminate | `godui-progress-indeterminate` | `transform` | `ease-out-expo` | 1.4s loop |

Under `prefers-reduced-motion` a new value snaps into place, and an
indeterminate bar fills the track and pulses its opacity instead of sweeping.

## API

Built on [Radix Progress](https://www.radix-ui.com/primitives/docs/components/progress).
Props are identical to [shadcn/ui Progress](https://ui.shadcn.com/docs/components/progress);
`value={null}` or no `value` makes the bar indeterminate.
